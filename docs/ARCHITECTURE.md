# Архитектура первого внутреннего прототипа

Пользователь делегировал выбор технологии 30.09.2026 в 23:47 МСК. Выбраны Python 3.12, SQLite, Tkinter/ttk. Причина: один локальный компьютер, файловые операции, простые формы для проверки бизнес-логики, отсутствие сетевых зависимостей при работе. Tauri/React/Rust были только ранним предложением.

- engineer_cabinet/core.py — бизнес-правила, SQLite, папки, операции, отчёты, журнал, копии.
- engineer_cabinet/ui.py — простые оконные формы; будущий визуал должен использовать то же ядро.
- main.py — запуск и восстановление.
- tests/ — проверки сохранения, денег, нумерации, ошибок файлов и форм.
- .github/workflows/windows.yml — тесты Windows и сборка переносимой папки с .exe.

Общий корень по умолчанию D:\\Кабинет инженера. Данные/cabinet.sqlite3 хранит записи и журнал. Просчеты и Заявки содержат обычные файлы. Резервные копии — ZIP базы и файлов раз в 7 дней при работе, не более трёх. Локальный указатель на корень — LOCALAPPDATA/EngineerCabinet/location.json; рабочих данных в профиле нет.

Длительные операции выполняются в отдельном рабочем потоке. UI показывает результат через очередь. Изменения базы сериализованы; второй экземпляр на тот же корень блокируется. Повтор удаления/переименования восстанавливается из сохранённого описания операции; номер освобождается после успешного удаления.

Сумма хранится целыми рублями после Decimal ROUND_HALF_UP; заработок — целочисленные 3% с округлением. Отчёт рассчитывается по сохранённым месяцу и году закрытия. Журнал изменений отделён от текущего состояния, хранит старые/новые значения.

Восстановление только в новую пустую папку. Внешние привязанные папки при восстановлении становятся локальными подпапками нового корня; исходные внешние файлы не перезаписываются.

Это внутренний прототип. Готовность к финальному визуалу определяется проверкой на Windows 11 пользователя. Запуск на облачном Windows не заменяет проверку конкретного диска D: и AutoCAD-файлов.

## Оформление по утверждённому макету

01.10.2026 внешний вид реализуется в текущей среде без смены ядра. ui.py связывает окна с бизнес-правилами; widgets.py рисует видимую часть таблицы, цветные метки, кнопки папок и редактор комментария. Отрисовка не создаёт виджет для каждой строки базы. Просчёты и заявки имеют общие сводные показатели заявок. Отчётность использует ту же таблицу и русские названия месяцев. Схема SQLite не меняется.
