# Архитектура — предложение

## Основа

| Часть | Предлагаемый инструмент | Назначение |
| --- | --- | --- |
| Интерфейс | React + TypeScript + CSS | Таблица, карточка, настройки, отчёты |
| Разработка интерфейса | Vite | Запуск и сборка |
| Настольная оболочка | Tauri 2 | Окно программы и локальные команды |
| Локальная логика | Rust | Папки, сохранение, проверка данных |
| База | SQLite | Записи, менеджеры, настройки, история |
| Среда | VS Code | Редактирование и локальная проверка |
| Автоматизация | GitHub Actions | Проверки и будущая Windows-сборка |

Стек не утверждён окончательно. Версию Windows нужно уточнить.

## Данные и папки

Рабочая база находится в каталоге данных установленной программы, вне исходников и папки установки. Рабочий корень заданий выбирается в настройках. Запись хранит внутренний ID и привязку к папке; номер для пользователя не заменяется этим ID.

Длительные файловые операции не блокируют интерфейс. Ошибки доступа, существующие папки и повторные запросы обрабатываются явно. Содержимое вручную привязанной папки сохраняется.

Резервная копия базы и копия файлов — разные операции. Расписание, место хранения и восстановление ещё согласуются.

## Автоматизация по этапам

1. Сейчас: документы проекта и проверка пробелов/конфликтных маркеров при изменениях.
2. После утверждения стека: исходники, фиксированные зависимости, проверка TypeScript, сборка интерфейса и проверки бизнес-логики.
3. После появления приложения: Windows-сборка и установщик в результатах GitHub Actions.
4. Проверка на рабочем ПК: выбор корня, создание и открытие папок, перезапуск, обновление с сохранением данных.

Автообновление установленной программы — отдельный этап. Постоянный фоновый агент не настроен.

GitHub даёт доступ к проекту, но не к дискам ПК. Для локальной работы нужен отдельно настроенный локальный агент или запуск пользователем.
