# Бизнес-логика — v0.2

Актуализировано по словам пользователя 30.09.2026. Основные требования — [ТЗ](SPEC.md); пошаговое описание для Camunda и разработки — [План](IMPLEMENTATION_PLAN.md).

## Подтверждено

- Программа на одном компьютере; автоматическое создание папок; работа без Google.
- Просчёт: выбор менеджера → автоматическая дата → следующий номер в отдельном счётчике этого менеджера → запись и папка.
- Пользователь кладёт файлы в папку и работает в AutoCAD самостоятельно.
- У просчёта только «В работе» и «Готово»; готовность отмечается вручную.
- Заявка: ручной номер → запись и папка; связь с просчётом необязательна.
- Заказчик не нужен в основном сценарии и обязательных полях.
- В заявке есть менеджер, общая сумма и комментарий. Комментарий строки и карточки — одно поле.
- Статусы заявки согласуются позже; не наследуются автоматически из CRM.
- Суммы, бонусы и месячная отчётность остаются в объёме; финансовые правила не определены.
- Порядок: схема пользователя → согласование → внутренняя реализация → проверка → визуал.

## Предлагаемая адаптация

Менеджер заявки подставляется из связанного просчёта; без просчёта выбирается вручную. Это толкование слов «менеджер подгружается», требующее проверки.

Для файлов пока не выбран способ подгрузки просчёта. До согласования не копировать/не переносить их автоматически. Первоначальный статус просчёта «В работе», возврат на доработку и сортировка по статусу/дате пока предложения.

База и файловая система не образуют единую транзакцию. Предлагается сохранять внутренний ID и состояние подготовки папки pending / ready / error. Повтор создания папки продолжает ту же операцию. Это не дополнительные рабочие статусы просчёта.

Предлагается сохранять файлы при отмене/удалении записи; не перезаписывать существующие папки; восстанавливать путь через выбор новой привязки.

## Что решить по схеме

1. Точный формат номера просчёта, сброс и повторное использование счётчика. Его отдельность для менеджера уже подтверждена.
2. Переход «Готово» → «В работе» и автоматический начальный статус.
3. Связь заявки с просчётом: ссылка на папку, копирование или перенос файлов? Возможны несколько заявок?
4. Подстановка/ручной выбор/смена менеджера заявки.
5. Статусы заявки, условия завершения, сортировки и отмена.
6. Уникальность и изменение ручного номера, переименование папки.
7. Точная структура корня и подпапок.
8. Расчёт/ручной ввод бонуса, финансовый месяц, начисление и выплата.

История сортировок и расхождения CRM сохранены в разделах 15–19 ТЗ. Старые статусы просчёта заменены последними словами пользователя. Бонусы цеха нельзя второй раз прибавлять к общему активному бонусу.
