# Бизнес-логика

Статус: проект правил. Подробный состав инженерных полей и перенесённых функций находится в [ТЗ](SPEC.md).

## Подтверждено

- Один пользователь самостоятельно ведёт записи.
- Номер заявки ручной; создание добавляет строку и связанную папку.
- Просчёт получает менеджера, счётчик и дату.
- Комментарий строки и карточки — одно поле.
- Статусы личные. Изменения не запускают действия других сотрудников.
- Задания и остальные файлы находятся в папках.
- Учитываются суммы и бонусы; формула пока не задана.

## Предлагаемые сценарии

| Действие | Результат | Обработка ошибки |
| --- | --- | --- |
| Создать заявку | Запись с ручным номером; папка по шаблону | Явное состояние подготовки; повтор не дублирует запись |
| Создать просчёт | Номер после выбора менеджера; запись и папка | Выделение счётчика согласовано с сохранением; сбой папки повторяем |
| Привязать папку | Сохранён существующий путь | Не перезаписывать файлы; показать недоступный путь |
| Изменить комментарий | Одинаковый текст в строке и карточке | Сохранить введённый текст при ошибке |
| Открыть папку | Открыт системный проводник | Предложить восстановить привязку |
| Отменить запись | Сохранить историю и файлы | Не удалять папку автоматически |

База и файловая система не образуют одну транзакцию. Предлагается состояние `pending / ready / error` для подготовки папки, с повторяемой операцией и стабильным внутренним ID записи. Это техническое предложение.

## Решения пользователя до реализации

1. Может ли один просчёт породить несколько заявок?
2. Что завершает заявку: готовность чертежа, отправка в цех, УПД или отдельная отметка?
3. Бонус вводится вручную или рассчитывается? Какая база и ставка?
4. По какой дате бонус относится к месяцу? Нужно ли различать начисление и выплату?
5. Как выглядит номер просчёта? Счётчик отдельный для менеджера? Когда сбрасывается?
6. Где уникален номер заявки? Что происходит с папкой при его изменении?
7. Какая точная структура подпапок? Как привязываются существующие?
8. Какие статусы, поля и правила сортировки обязательны?

Нельзя принимать цифры старых примеров за ставку бонуса. Проблема не означает завершение. Итог по заданиям в цеху нельзя повторно прибавлять к общему активному бонусу.
