# Состояние проекта

Обновлено 30.09.2026, рабочая версия требований v0.2.

## Сделано

- Доступ к репозиторию подтверждён; начальная проверка документов прошла на предыдущем изменении.
- В ТЗ внесены независимые счётчики менеджеров, автоматические даты, два статуса просчёта, необязательная связь заявки с просчётом и отсутствие обязательного заказчика.
- Создан [пошаговый план](IMPLEMENTATION_PLAN.md) для схемы в Camunda и разработки.
- С этого уточнения docs/SPEC.md — рабочее ТЗ; документы Drive — история первоначального обследования, этим изменением не обновлены.
- VS Code установлен пользователем. Локальный Codex ещё не подключён.

- Подготовлена [стартовая выгрузка чату Camunda и бизнес-логики](BUSINESS_LOGIC_CHAT_START.md): установка, обучение, схемы, экспорт и возврат результатов главному чату.

## Текущий этап

Пользователь составляет бизнес-логику, сначала просчёт, затем заявку. Ожидаемый исходник — .bpmn; схемы можно хранить в docs/processes/. После передачи сверяем правила и фиксируем объём первого выпуска.

## Не реализовано

Нет исходников приложения, рабочей базы, создания папок, установщика и доступа чата к дискам ПК. Стек и бизнес-правила по открытым вопросам ещё не утверждены. Постоянный фоновый агент не настроен.

## Порядок дальнейшей работы

Схема → согласование → подключение/проверка среды → внутренняя реализация с простыми формами → проверка на ПК → визуальный чат → интеграция и установщик.

Разработку приложения не начинать до передачи и согласования схемы. Визуал — после внутренней реализации. Подключение локального Codex обсудить, когда пользователь сообщит о готовности.
